# s00 design log

Stage: s00 · Toolchain (compile, link, strict warnings)
Type: mental-model talk, no code interface.

## Talk 1

Q1 (compiler vs linker, "undefined reference"):
- Learner: compiler makes the .o (machine code); linker combines .o files into an executable; "undefined reference" is a linker error.
- Feedback: correct. Missing piece noted: the compiler is also where syntax and type errors and warnings come from, and the linker also pulls in libraries. Not an error, just the full picture.
- Status: Q1 agreed. Next: Q2.

Q2 (debug vs release):
- Learner: debug lets you run a debugger; release skips that setup to run fast; debug for development, release for the final build.
- Feedback: right on purpose. Vague on mechanism: debug adds debug info (-g) and turns optimization off (-O0); release turns optimization on (-O2) and usually drops the debug info.
- Learner, follow-up: "it dropped the map" (partly right: release usually omits -g). Then "if you can map back to the line it's fine" (wrong: optimized code can interleave, or have no value to show).
- Learner, follow-up: why can't the debugger read a register. Explained: registers are shared scratch space, and variables may have no stable location. Learner's answer: the optimizer keeps values in registers, and -O0 keeps them at fixed addresses so the debugger can trace them. Mostly right; tighter version: at -O0 every assignment writes to memory, so there's always a stored copy.
- Status: Q2 agreed with corrections. Next: Q3.

Q3 (why warnings as errors, and the cost):
- Learner: some warnings (like a value going below 0) should be errors, and you can turn a warning into an error.
- Feedback: the lives example is a real bug the warning catches. Missing: why the team wants the build to stop. Status: open, asked about warning #201 and the cost.
- Learner: without -Werror, warning #201 is skipped; with it, the build stops. Cost: fixing normal warnings by hand, or adding ignores.
- Status: Q3 agreed. The cost is worth paying; the fix is clearer code, not turning the flag off.

Q4 (what goes wrong with extensions):
- Learner: extensions aren't standard, so the code may not transfer across compilers.
- Learner, follow-up: with -pedantic-errors, `int grid[n];` doesn't compile at all.
- Status: Q4 agreed.
